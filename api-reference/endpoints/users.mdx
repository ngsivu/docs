The Users API gives you programmatic control over user accounts within your Google workspace. Use these endpoints to provision new users and retrieve a full list of workspace members. All user endpoints require a valid API token with the appropriate `users:read` or `users:write` scope — see the [Authentication guide](/api-reference/authentication) for details on obtaining and using tokens.

---

## GET /v1/users

Retrieve a paginated list of all users in your workspace. Use query parameters to filter, sort, and paginate results.

### Query Parameters

<ParamField query="page" type="integer" default="1">
  The page number to retrieve. Starts at `1`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Number of users to return per page. Accepted values: `1`–`100`.
</ParamField>

<ParamField query="sort" type="string" default="created_at">
  Field to sort results by. Accepted values: `created_at`, `updated_at`, `email`, `name`.
</ParamField>

<ParamField query="order" type="string" default="desc">
  Sort direction. Accepted values: `asc`, `desc`.
</ParamField>

<ParamField query="filter[status]" type="string">
  Filter users by account status. Accepted values: `active`, `suspended`, `pending`.
</ParamField>

<ParamField query="filter[role]" type="string">
  Filter users by assigned role. Example: `admin`, `editor`, `viewer`.
</ParamField>

### Request

```bash title="List Users"
curl --request GET \
  --url 'https://api.google.com/v1/users?page=1&limit=20&sort=created_at&order=desc' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json'
```

### Response Fields

<ResponseField name="data" type="array">
  Array of user objects matching the query.

  <Expandable title="User object">
    <ResponseField name="id" type="string">
      Unique identifier for the user, prefixed with `usr_`.
    </ResponseField>
    <ResponseField name="email" type="string">
      The user's primary email address.
    </ResponseField>
    <ResponseField name="name" type="string">
      The user's full display name.
    </ResponseField>
    <ResponseField name="role" type="string">
      The user's assigned role within the workspace.
    </ResponseField>
    <ResponseField name="status" type="string">
      Current account status: `active`, `suspended`, or `pending`.
    </ResponseField>
    <ResponseField name="avatar_url" type="string">
      URL of the user's profile photo.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the account was created.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 timestamp of the most recent account update.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object">
  Pagination metadata for the response.

  <Expandable title="Meta object">
    <ResponseField name="total" type="integer">
      Total number of users matching the query across all pages.
    </ResponseField>
    <ResponseField name="page" type="integer">
      The current page number.
    </ResponseField>
    <ResponseField name="limit" type="integer">
      Number of results per page.
    </ResponseField>
    <ResponseField name="total_pages" type="integer">
      Total number of pages available.
    </ResponseField>
  </Expandable>
</ResponseField>

## POST /v1/users

Create a new user account in your workspace. The new user receives an email invitation to set their password and complete onboarding.

### Body Parameters

<ParamField body="email" type="string" required>
  The email address for the new user. Must be unique within your workspace.
</ParamField>

<ParamField body="name" type="string" required>
  The user's full display name.
</ParamField>

<ParamField body="role" type="string" required>
  The role to assign. Accepted values: `admin`, `editor`, `viewer`.
</ParamField>

<ParamField body="send_invite" type="boolean" default="true">
  When `true`, sends an invitation email to the new user immediately upon creation.
</ParamField>

<ParamField body="metadata" type="object">
  Optional key-value pairs to attach to the user record. Useful for storing external IDs or custom attributes.
</ParamField>

### Request

```bash title="Create User"
curl --request POST \
  --url 'https://api.google.com/v1/users' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "email": "alice.martin@example.com",
    "name": "Alice Martin",
    "role": "editor",
    "send_invite": true,
    "metadata": {
      "department": "engineering",
      "employee_id": "EMP-00421"
    }
  }'
```

### Response

```json title="201 Created"
{
  "data": {
    "id": "usr_01HXYZ345678MNOPQR",
    "email": "alice.martin@example.com",
    "name": "Alice Martin",
    "role": "editor",
    "status": "pending",
    "avatar_url": null,
    "metadata": {
      "department": "engineering",
      "employee_id": "EMP-00421"
    },
    "created_at": "2024-07-10T09:00:00Z",
    "updated_at": "2024-07-10T09:00:00Z"
  }
}
```

<Note>
  A newly created user has a `status` of `pending` until they accept their invitation and complete account setup. You can retrieve the current status for any user by calling `GET /v1/users` and filtering by the user's ID.
</Note>

### Response Fields

<ResponseField name="data" type="object">
  The newly created user object. See the [List Users](#get-v1-users) response fields for a full description of each property.
</ResponseField>
